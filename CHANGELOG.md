# Changelog

## Unreleased

### Breaking

- **Listeners: no TCP port by default, auth on by default.** xtcp2 now serves health, metrics and the link monitor's detail paths on one Unix socket, `/run/xtcp2/metrics.sock` (mode `0600`), with a raw bearer token from `LISTENER_RAW_TOKEN_FILE`, and exits 64 without one. It no longer listens on `:9088` or `:8889`: gRPC, pprof and `/ip` are served only by a listener that names them. `-listener` (repeatable) / `LISTENERS` describes each listener, its credentials (files only) and the classes it serves: `health`, `metrics`, `metrics-detail`, `ip`, `debug`, `grpc-read`, `grpc-admin` ([listeners](docs/security.md#listeners)). TCP must be typed (`network=tcp`) and needs a credential unless it is loopback or serves health alone; `debug` and `grpc-admin` need an admin credential; pprof never serves `cmdline`. A `grpc-read` listener answers admin RPCs `Unimplemented`. Bad listener config, a missing token or token file exits 64; `ConfigService.Set` refuses the same.
- **The per-listener flags are deprecated.** `-promListen*`, `-grpcPort`, `-grpcListen*`, `-grpc*UnixSocket*`, `-linkMonitorIPListen` and their variables still work, expanded to listeners with a `DEPRECATED` line naming the `-listener` equivalent; the Prometheus listener they describe no longer serves pprof, and as TCP it now needs a token. Giving them with `-listener` exits 64. An empty `-listenerAuthMode` / `LISTENER_AUTH_MODE=` now means unset (raw), not disabled.
- **Clients dial the gRPC socket.** `xtcp2ctl` and `xtcp2client` default to `unix:/run/xtcp2/grpc.sock`; pass `-network tcp` for a TCP listener. The OCI images expose no ports, and `-healthcheck` probes the listener serving `health` from the same settings as the daemon. The NixOS module gains `listeners` and `listenerTokenFile` (null generates a token once, at `/var/lib/xtcp2/listener-token`); `linkMonitor.ipListen` becomes a loopback `ip` listener. New gauge `xtcp2_listener_active{name,network,class}`.
- **S3 uses TLS unless told otherwise.** A bare `host:port` S3 endpoint now uses TLS (it was plaintext), and `http://` is refused at startup (exit 64) unless `-s3AllowInsecure` / `S3_ALLOW_INSECURE=true`, which logs a warning and sets `xtcp2_s3_insecure 1`. TLS 1.2 is the minimum; `-s3CAFile` / `S3_CA_FILE` adds a private CA. `ConfigService.Set` refuses a plaintext endpoint without the opt-in.
- **Credentials on the command line.** The production (slim) flavors refuse `-s3AccessKey`, `-s3SecretKey` and the four `-listener*` secret flags with exit 64; development builds warn, now for the S3 flags too and even when the env var is also set. Use the `_FILE` variables.
- **`_FILE` secrets are checked.** A missing or unreadable `*_FILE` path, a non-regular file, or one readable by group or others stops startup with exit 64. It used to be ignored silently (listener tokens) or logged (S3 keys), leaving the credential empty. Mount secrets mode `0400`.
- **The debug writers are build-time opt-ins.** The netlink capture writer (`-writeFiles` / `-capturePath`) is compiled in only with `-tags capture`, which no flavor or image sets; use `nix build .#xtcp2-capture`. The `file:` destination needs `-tags dest_file` and is in the full (development) flavor only, so `xtcp2-<dest>` slim flavors and their images no longer have it. Asking for either on a binary without it exits 64 at startup with the tag to rebuild with; `ConfigService.Set` refuses it with `FailedPrecondition`. A capture build reports `+capture` in its version line, and when armed logs a warning and sets `xtcp2_debug_capture_enabled 1`.
- **`/ip` and the daemons carry no netlink write verbs.** goip's write verbs and `pkg/xtcpnl`'s write builders compile only with `-tags goip_write`, which only `goip` and `goip-parity` are built with. `/ip` on xtcp2 and go-link-monitor answers a write verb 400 as before; an untagged `goip` answers one `ErrWriteNotCompiled` (exit 1), so a `go build ./cmd/goip` that needs them must add the tag. The Nix `goip` and `goip-parity` store names gain `-goip_write`; their binary paths are unchanged. `checks.no-write-encoders` proves the daemons link no write encoder and import no `os/exec` (bar minio-go's credentials provider).
- **Operator strings reject control characters.** `hostname`, `location`, `label` and `tag` (flags, env or `ConfigService.Set`) now fail validation, exit 64, if they hold a C0 control, DEL or a C1 control; their length limits are unchanged.
- **IPv6 sockets are collected.** xtcp2 asked the kernel for `AF_INET` sockets only, so every `AF_INET6` socket went unrecorded, including Go's dual-stack `0.0.0.0` listeners and the connections they accept. Each poll now dumps `AF_INET`, then `AF_INET6`, on each namespace's netlink socket (one dump at a time, so `poll_end` still means every namespace finished). Hosts with IPv6 or dual-stack services record more rows per poll. `-maxDumpBytes` and `-maxRecordsPerNetns` are a namespace's budget across both dumps. The socket-count gate adds `/proc/net/sockstat6` (`TCP6: inuse`), which takes one more fd per namespace (5 with the gate on). A dual-stack socket's IPv4 peer reads `::ffff:a.b.c.d`: treatment attribution, candidate discovery and evidence analysis treat it as the IPv4 address, and golden-record scrubbing numbers it with the IPv4 addresses. New counter `Poller/dumpInet6`.

### New

- **The S3 upload queue never blocks polling.** It used to block the poller once 16 envelopes were waiting for a slow or unreachable S3. Now `-s3QueueDepth` (default 16, max 4096) and `-s3MaxBufferedBytes` (default 64 MiB, `0` = no byte bound) bound it, and past either it drops the oldest envelope. Drops are counted in `xtcp_s3_dropped_total{reason}` and `xtcp_s3_dropped_bytes_total{reason}`; `xtcp_s3_buffered_bytes{stage}` shows what is held, and `queueFull` now counts drops. Env `S3_QUEUE_DEPTH`, `S3_MAX_BUFFERED_BYTES`; startup-only (`ConfigService.Set` keeps the running values). Budget ≈ `-s3MaxBufferedBytes` + the flush threshold + one upload ([design](docs/design-jitter-and-backoff.md#back-pressure--memory)).
- **S3 spill directory.** `-s3SpillDir` / `S3_SPILL_DIR` keeps Parquet objects that failed to upload on disk and uploads them, oldest first, once S3 is back, including after a restart. With it the worker tries each upload once and spills on failure, so it keeps draining the queue during an outage. `-s3SpillMaxBytes` / `S3_SPILL_MAX_BYTES` (default 1 GiB) bounds the directory, deleting the oldest past it. Metrics `xtcp_s3_spill_total{result}`, `xtcp_s3_spill_objects`, `xtcp_s3_spill_bytes`. Off by default; startup-only ([design](docs/design-jitter-and-backoff.md#spill-directory)).
- **Strings from tenants and the network are cleaned.** Container names and images, a tenant's interface names, LLDP and NIC strings, the ASN feed's network owner, netns names and congestion names are cut to 256 bytes (16 for interface and congestion names) at a UTF-8 boundary. Invalid UTF-8 and control characters (C0, DEL, C1) become U+FFFD. Each is cleaned once, where it enters, not per row.
- **Per-namespace caps.** `-maxDumpBytes` (default 256 MiB) and `-maxRecordsPerNetns` (default 262144) bound one namespace's dump per poll: packets past the byte cap are drained undecoded, and records past the record cap are dropped before decode. `-maxNetns` (default 4096) bounds the namespaces tracked. At the cap, tracked namespaces keep their slots, and new ones wait for a freed slot, first come, first served. Alert on `xtcp_netns_dropped_total`. Drops are counted in `xtcp_dump_dropped_total{reason}` and `xtcp_netns_dropped_total`, with one log line per truncated dump or short reconcile. `0` turns a cap off; the matching env vars are `MAX_DUMP_BYTES`, `MAX_RECORDS_PER_NETNS` and `MAX_NETNS`. The caps are startup-only: `ConfigService.Set` keeps the running values. No healthy host should reach the defaults; a host that does now loses that namespace's excess rows, where it used to collect them all ([polling and batching](docs/polling-and-batching.md#per-namespace-caps)).
- **Socket-count gate, reconcile limits, per-owner quota.** Before each poll xtcp2 reads each namespace's sockstat (an fd opened in the namespace; `pread`, or io_uring batches with `-ioUring`) and, when the total is over `-maxRecordsPerPoll` (default 1,048,576), degrades only the namespaces over their fair share: first TIME_WAIT/SYN_RECV are not asked for, then one of K port shards is dumped per poll. `-maxNetnsPerOwner` (default 64) caps namespaces tracked per owner (the container runtime's cgroup), `-maxNetnsAddsPerReconcile` (256) the adds per reconcile, and `-reconcileTimeout` (1s) the namespace scan; a timed-out scan deletes nothing. New metrics `xtcp_poll_sockets`, `xtcp_poll_degraded_total{level}` and `xtcp_reconcile_incomplete_total{reason}`; `xtcp_netns_dropped_total` gains `reason`. `0` turns each off; all are startup-only. Each tracked namespace now holds four fds (was two: sockstat and `ip_local_port_range` are new), and xtcp2 warns at startup when `RLIMIT_NOFILE` can't cover them ([polling and batching](docs/polling-and-batching.md#socket-count-gate), [network namespaces](docs/network-namespaces.md#configuration)). The analysis behind an upstream all-namespace dump is in [docs/kernel](docs/kernel/inet-diag-all-netns.md).
- **Fuzzing every target.** `fuzz-all` (dev shell, `nix run .#fuzz-all`) finds every Go fuzz target with `go test -list` and fuzzes each in turn; `checks.test-fuzz-all` runs it sandboxed at 10 s per target, so `nix flake check` fuzzes again whenever the source changes. Two new fuzzers cover tenant-reachable paths: `FuzzDockerProjection` (a Docker inspect body to a container's name and image) and `FuzzRowFromProto` (an S3 envelope through Parquet and back). `FuzzClean` now also checks idempotence and the fast path. The first run found `/ip/vrf/show/NAME` returning 500 for a name that is no VRF; it is now a 404. Docker container list and inspect bodies are now streamed, keeping only the fields used: memory stays bounded however large a container's labels are, a container whose entry passes 4 MiB is skipped and logged (never the whole list), each request has a 10 s timeout, and an oversized `/events` line no longer stalls container-metadata refresh. Limits: [Docker API limits](docs/design-metadata-enrichment.md#docker-api-limits).
- **Golden records.** `nix run .#capture-golden-records` captures one poll of the production binary in a microVM over a fixed workload (3 containers, a named netns, the host). It commits the poll scrubbed, under `pkg/xtcp/testdata/golden/`. `xtcp2-golden diff` compares two captures and ignores run-to-run noise (timestamps, cookies, ephemeral ports, counter values, addresses). It still catches a missing attribute or a changed container name. `checks.golden-records` keeps the fixture scrubbed and consistent, and its rows seed `FuzzRowFromProto` ([Golden records](nix/README.md#golden-records)).
- **Golden-record shapes.** `xtcp2-golden profile` reduces a capture to its shape (populated columns, enum values, families, kinds of namespace) with no identity in it, and `xtcp2-golden shape-diff` compares two, so a capture from a real host can be checked against the microVM fixture although the workloads differ. `pkg/xtcp/testdata/golden/coverage.json` lists the columns, values, families and kinds of namespace every fixture must exercise; `check` (and so `checks.golden-records`) fails a fixture that falls short ([Golden records](nix/README.md#golden-records)).
- **Socket options on the traffic tools.** `tcp_client` and `tcp_server` take `-cong`, `-tos`, `-priority`, `-rcvbuf`, `-freebind`, `-transparent` and `-bindNoPort`, and `tcp_client` takes `-bulk`, `-close` and `-halfclose` (`tcp_server -holdEOF` holds the other end), so a test workload can give the collector sockets with a chosen congestion algorithm, TOS, class_id, window scale, sockopt bits and TCP state. The OCI image passes `TCP_CLIENT_ARGS` / `TCP_SERVER_ARGS` through ([integration testing](docs/integration-testing.md#tcp_server--tcp_client--socket-population)).
- **Golden records cover the fleet's columns.** The capture workload adds four netns pairs: one connection per congestion algorithm the kernel offers (IPv4 and IPv6; every `tcp_*` module is loaded), bulk transfers over netem loss and reordering, TOS/traffic class, priority, the sockopt bits and three window scales, and TIME_WAIT, SYN_SENT, FIN_WAIT2 and CLOSE_WAIT sockets in exact numbers. Three MTUs give three pmtu/MSS pairs. `coverage.json` requires the per-algorithm info structs, the loss counters, the new states and values, and every algorithm in the capture's `cong_available`. `ROW` lines on the VM console check each pair ([Golden records](nix/README.md#golden-records)).
- **Golden records cover NICs, locality and ASN.** The capture VM gains a second uplink (an emulated e1000e) and a 10000 Mb/s virtio NIC, and the collector enriches locality and ASN against an artifact built from documentation prefixes. A netns trio gives one connection per locality (self, subnet, remote over IPv4 and IPv6). `coverage.json` requires the uplink 2 columns, the NIC speeds, localities 1–3, the ASN, owner and egress columns, and the bound interface name.
- **Golden records: no flaky keepalive probe, exact loss rows, a one-way sequence flow.** Idle golden sockets use `-keepalive 1h`, so a poll no longer catches a probe in flight. New rows `netem_retrans_a`/`_b` require xtcp2's sum of `total_retrans` to equal each netem namespace's `TcpRetransSegs`, and `netem_kernel_agrees` each bulk client's to equal `ss`'s; the bulk clients wait 30 s to connect, so a dropped SYN no longer closes a socket, and golden-bulk-a turns off the ECN fallback, so a dropped SYN no longer turns dctcp into dctcp-reno (new row `bulk_dctcp_ecn`). The sequence flow is one-way (new `tcp_server -discard` and `tcp_client -bulkOneWay`), so its retransmits must equal the 12 drops, and `xtcp2-golden diff` now compares its rows ([design](docs/design-rocm-ernic-tests.md#round-3-close-the-two-golden-flakes-strict-diff-on-the-sequence-flow)).
- **Golden records check the emulated NICs against xtcp2.** After a capture, the runner stops the rocm-ernic servers cleanly and `ernic-oracle` (`checks.ernic-oracle`) compares their own fault counts with the guest's NIC counters. It also compares the frames each NIC sent or delivered with the `tcp_info_segs_out` and `segs_in` xtcp2 recorded, which must be exactly equal. A third and fourth ionic NIC carry one cubic flow through a fixed drop sequence (12 drops). The ernic transfers turn TCP keepalive off (new `-keepalive` flag on `tcp_client` and `tcp_server`), and the emulator's bridges turn multicast snooping off, so no frame outside the transfers reaches the counters. `ernic-run-many --pcap IFNAME` records a fabric interface ([design](docs/design-rocm-ernic-tests.md)).
- **Golden records on an emulated ionic NIC.** The capture VM's uplink 1 is now an AMD Pensando ionic NIC emulated by [rocm-ernic](https://github.com/ROCm/rocm-ernic) over vfio-user (PCI 1dd8:1002, 100000 Mb/s, firmware from an xtcp2 NIC profile); e1000e stays uplink 2 and virtio is kept for management. The `rocm-ernic` input now pins upstream `ROCm/rocm-ernic` by rev and narHash, recorded in `nix/upstream-pins.json` and checked by `checks.ernic-pin` and `checks.upstream-pins`. `nix/ernic/` describes NICs as data (`checks.ernic-nics`) and runs one server per NIC with `ernic-run-many` (`checks.ernic-run-many`). A second ionic NIC in netns `golden-ernic-b` carries one 4 MiB transfer per bulk algorithm with the emulator's deterministic drops (every 50th frame); `ROW` lines check the drop count exactly, and `xtcp2-golden diff` treats those rows like the netem pair's (`Options.FaultNetns`, `FaultEgress`). Listener drops, `rqueue` and receive memory are no longer compared on lossy rows ([design](docs/design-rocm-ernic-nics.md)).
- **Vulnerability check.** `checks.govulncheck` runs govulncheck against a pinned snapshot of the Go vulnerability database, with no tags and with every flavor tag, and fails on a reachable finding not in its accepted list. One is accepted: GO-2026-6859 in `net/http`, fixed in go1.27.4, until the toolchain moves. `nix run .#govulncheck-fresh` checks against the live database and runs `go mod verify`; `nix build .#sbom-<binary>` writes a CycloneDX SBOM for any binary package.

### Fixes

- **Uplinks follow a route change.** The uplink columns were chosen once at startup, so after a route-metric swap they still named the old uplink until a restart, while egress and locality had moved. Auto-detected uplinks are now re-read every `-localityRefreshInterval` (default 60s, 0 = never; pinned `-uplinkInterfaces` are never re-read). An unchanged list costs one `/proc` read; a changed one is read again from sysfs and lldpd and swapped in whole. New counter outcomes under `function="refreshUplinks"`: `unchanged`, `changed`, `lldp_error`.
- **Egress follows the lowest route metric.** With two routes for the same prefix, `enrich_socket_dest_egress_ifname` named the one listed last, which the kernel lists by ascending metric, so it was the highest-metric route. That is the one the kernel uses last. The lowest metric now wins, and on a tie the first route listed, as in the kernel's lookup.
- **Congestion names are matched whole.** `inet_diag_cong_enum` came from the first three letters, so `dctcp-reno` (DCTCP's fallback when ECN isn't negotiated) read as DCTCP and any name starting `cub` as CUBIC. Names now match exactly: `dctcp-reno` and look-alikes are UNSPECIFIED with their name kept, `bbr1` is BBR1, and `prague` gets its enum. A 2-letter name (`nv`, `lp`) without NLA padding is accepted (the minimum was 4 bytes). The in-tree names are now constants, so decoding them no longer allocates.
- **`nsid` 0 is no longer ambiguous.** The kernel's first namespace id is 0, which read the same as "no id" and as `-populateNsid` off; Docker gives its containers ids 0, 1, 2… in creation order, so one container per host had the ambiguous 0. New column `nsid_assigned` (proto tag 33, a free slot, so no record epoch bump) is true exactly when `nsid` holds an assigned id: filter on it, not on `nsid != 0`. Existing ClickHouse deployments add it with `build/containers/clickhouse/sql/migrations/nsid-assigned.sql`; rows from older daemons read false. The CSV/TSV default columns gain it after `nsid`, shifting the later columns by one. Golden records compare `nsid` again, numbered like the other ids.
- **Socket addresses could belong to another socket.** The decoder kept the source and destination as slices of the netlink receive buffer. That buffer goes back to the pool once its packet is decoded and is reused for later packets, while the record waits for the poll's flush. So in any namespace whose dump took more than one packet, earlier records could carry later bytes. Records now own a copy. A recycled record reuses its copy; only a new record allocates, one 32-byte array. The microVM `tcp-families` check found it: `AF_INET` rows carried `AF_INET6` addresses.

## 0.2.1 (2026-11)

Fixes for what the first fleet rollout of 0.2.0 found: the link monitor baseline, the uplink columns, and container attribution. No schema, flag-default or `XtcpConfig` change; 0.2.0 clients and consumers work unchanged.

### Upgrade checklist

1. **Mount the netns dirs `rslave`** in a container deployment (`-v /run/netns:/run/netns:ro,rslave`, the same for `/run/docker/netns`). Without it, pods started after xtcp2 are not collected; 0.2.1 now warns at startup and sets a gauge (below).

### New

- **Link monitor learn deadline.** `-linkMonitorLearnDeadline` (`LINK_MONITOR_LEARN_DEADLINE`, `link_monitor.learn_deadline`; go-link-monitor `-learn-deadline`), default 5m, 0 waits forever. If no baseline is learned by then, the visible up count becomes a provisional baseline, so `up_links_delta` still reports when the count never becomes ready (a stuck RDMA port, a hardware fault). It is kept in memory only, never written to the baseline file, and flagged by the sparse `go_link_monitor_baseline_provisional 1`; a normally learned baseline replaces it and is saved.
- **Netns mount propagation check.** In a container, `/run/netns` and `/run/docker/netns` must be mounted `rslave` (`-v /run/netns:/run/netns:ro,rslave`). With Docker's default `rprivate`, namespaces created after xtcp2 starts are invisible: their sockets aren't collected and their container name/image stays empty. xtcp2 now logs a warning at startup and sets `xtcp_gauges{function="checkNetnsPropagation",variable="private",type="<dir>"}` to 1 for each such dir.
- **`goip vrf show NAME`**, `ip`'s `ipvrf_get_table` single lookup: prints `NAME TABLE`, `Invalid VRF` (exit 1) for a device that isn't a VRF, and table 254 for `default`. Byte-for-byte with iproute2 7.2.0; the parity matrix is 510 rows, 509 gated.

### Fixes

- **Link monitor baseline never written on most prod hosts.** Two causes, found on 78 of 105 hosts: the stock Ubuntu `ib_core` answers the RDMA netlink event subscription with `EOPNOTSUPP`, which was retried every 30 s and kept the count unready; and the bonding module's `/sys/class/net/bonding_masters`, a regular file, failed the RDMA netdev walk. A kernel without RDMA events now falls back to polled RDMA state (reported once, as `rdma_events` support `unsupported`), and non-netdev entries are skipped.
- **Uplink columns: `lo` as UPLINK2, empty NIC and LLDP columns.** Automatic uplink detection took the kernel's `unreachable ::/0 dev lo`, which every host has, as a default route, and used a bond itself as the uplink, which has no NIC attributes and no LLDP neighbour. Only up, non-reject default routes off `lo` count now, and a bond, vlan or bridge holding the route is replaced by the physical NICs beneath it. `-uplinkInterfaces` is unchanged.

## 0.2.0 (2026-10)

The first tagged release. These notes compare against `32a4fed4` (2026-08-17), the last revision most deployments built from; that tree also said `0.1.0` in `VERSION`.

### Upgrade checklist

1. **Update every consumer of the records before the daemons.** Schema epoch 2 renames columns (below); a table that maps by column name reads the renamed ones as NULL until it knows the new names.
2. **Upgrade `xtcp2ctl` and `xtcp2client` together with the daemon.** `XtcpConfig` was renumbered, and an old client talking to a new daemon (or the reverse) gets garbled config from `Get`/`Set` with no error.
3. **Give the daemon a writable `/var/lib/xtcp2`.** The link monitor is on by default and keeps its baseline there. If it can't create the directory or its lock file (a read-only root filesystem without that mount, say), the link monitor stops: `xtcp_gauges{function="linkMonitor",variable="up"}` reads 0 and its paths answer 503. Collection carries on either way. `LINK_MONITOR=false` turns it off.
4. **Check the listener TTL.** The Prometheus and gRPC TCP listeners now reply with TTL / hop limit 3, so a scraper more than three hops away gets no answer. Set `IPV4_TTL` / `IPV6_HOP_LIMIT` (0 = kernel default) for a distant scraper.
5. **Re-check `-netlinkers`** if you relied on the old default of 4.

### Breaking changes

- **Record schema epoch 2** (`schema_version = 2`). About twenty payload fields now use the kernel's struct member spelling, for example `tcp_info_rtt_var` → `tcp_info_rttvar`, `congestion_algorithm_string` → `inet_diag_cong`, `c_group` → `inet_diag_cgroup_id`. Three tags moved: `enrich_socket_dest_egress_ifindex` 301 → 311, `enrich_socket_dest_egress_ifname` 302 → 312, `inet_diag_cgroup_id` 2103 → 2003. The ClickHouse `Locality` enum label 2 is now `local_subnet` (was `connected_subnet`); the value is unchanged. Full table: [docs/record-versioning.md](docs/record-versioning.md#epoch-1--2-rename-table).
- **`XtcpConfig` renumbered** (part of epoch 2). Clients and daemon must match; see the checklist.
- **Changed defaults:**

  | Flag | Env | Was | Now |
  |---|---|---|---|
  | `-netlinkers` | `NETLINKERS` | 4 | 2 |
  | `-ipv4Ttl` | `IPV4_TTL` | 0 (kernel default) | 3 |
  | `-ipv6HopLimit` | `IPV6_HOP_LIMIT` | 0 (kernel default) | 3 |
  | `-linkMonitor` | `LINK_MONITOR` | (new) | true |

- **Changed meanings:**
  - `-netlinkers` now counts decoders per socket; one receiver reads each socket.
  - `-ioUring` covers netlink reads only; destination writes always use syscalls.
  - `-ioUringRecvBatch` is the number of receive buffers per socket (rounded up to a power of two), not SQEs per netlinker.
  - `-healthcheck` follows `PROM_LISTEN_NETWORK` (TCP or a Unix socket) and sends the configured listener credential.
- No flag or environment variable was removed or renamed; 52 were added.

### New

- **Link monitor, built in and on by default** ([design](docs/design-linkmonitor-in-xtcp2.md)). go-link-monitor runs inside xtcp2. `/metrics` carries only its problem summary (a handful of series plus one per active problem); `/metrics/<category>[/<iface>]` and `/metrics-all` serve the detail, collected on demand. It learns the expected up-link count on first start, persists it to `/var/lib/xtcp2/link-monitor-baseline.json`, relearns on SIGUSR1, and degrades to 503 on its own paths without stopping collection. `LINK_MONITOR=false` turns it off.
- **Destination IP metadata enrichment** ([docs](docs/ipfeed-asn-enrichment.md)). `-enrichAsn` stamps `enrich_socket_dest_asn` and `enrich_socket_dest_network_owner` from one lookup table built by `ipfeed-collector` from ~19 cloud and SaaS provider feeds. The `*-bootstrap` images carry a checked-in snapshot, so enrichment works from the first poll; `-asnDbPath` and `-asnRefreshInterval` pick up a fresher file from an `oci-ipfeed-collector` sidecar, and the daemon caches the last good table under `/var/lib/xtcp2/ipmeta`. `-enrichLocality` labels each destination self / local_subnet / remote and records the egress interface.
- **Listener authentication** ([design](docs/design-listener-security-hardening.md), [scraping](docs/observability.md#scraping-with-listener-auth)). `-listenerAuthMode` (`raw` or `hmac-utc-minute`) protects every path on the Prometheus listener and every gRPC method. `-listenerAdminAuthMode` adds a second credential for admin RPCs (config setters, link-monitor rebaseline and resync; any method not listed as read-only) and `/debug/pprof/`; the first then becomes read-only. Tokens can come from files (`LISTENER_RAW_TOKEN_FILE`, ...). Failures are delayed by a random 20–200 ms.
- **Unix socket listeners.** `-promListenNetwork unix` and `-grpcListenNetwork unix` serve the metrics and gRPC listeners on a socket, mode 0600 by default (`-promUnixSocketMode`, `-grpcUnixSocketMode`).
- **Admin gRPC API** with the read/admin split above, plus runtime setters such as `SetEnvelopeFlush`.
- **Accurate ECN**: 11 AccECN `tcp_info` columns, which were previously dropped at ingestion.
- **New tools**: `goip`, a read-only Go `ip` with byte-for-byte output parity for the objects it covers, also served under `/ip` with `-linkMonitorIPPaths` (off by default), or on a loopback listener of its own, without listener auth, with `-linkMonitorIPListen 127.0.0.1:9089`; `ipmeta-bootstrap`; `nix run .#update-ipmeta-bootstrap-lock` to refresh the snapshot.
- **RDMA**: the link monitor's RDMA collection is pure Go (netlink and umad); the cgo path is gone.

### Fixes

- A mid-poll envelope flush at the size cap no longer drops the records that triggered it.
- io_uring netlink reads keep packets in order (one multishot recv per socket).
- The daemon's own pid no longer keeps a network namespace it discovered alive.
- Signals are routed before flags are parsed, and a soft restart re-execs only after the profilers stop.
- `PROM_UNIX_SOCKET_MODE` / `GRPC_UNIX_SOCKET_MODE` are parsed as octal (`0660`) or decimal; values above `0777` are refused with a log line instead of setting stray mode bits.
- `ipfeed-collector`: Salesforce's feed, which lists several prefixes per record, parses again; the Microsoft 365 feed is requested with a valid client request id, which the service now requires.
- Hot-path Prometheus series are looked up once; two per-record series moved behind `-debugPrometheus`.

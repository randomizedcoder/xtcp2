## Update rules

- States are `not started`, `in progress`, `blocked`, `done` or `deferred`. There are no percentages.
- A task is `done` only when its "Done when" has passed and the evidence is in the [ledger](#verification-ledger).
- Evidence IDs (`V###` for code and VM runs, `DOC###` for docs) are immutable and append-only.
- Task IDs (`Cn-Tmm`, `Pn-Tmm`, `Gn-Tmm`) are never renumbered.
- Every task's commit flips its own checklist row and appends its `V###` rows.
- A phase's last task also closes the phase, following [Closing a phase](goip-parity-gaps.md#closing-a-phase):
  - it re-measures the assessment;
  - it updates the phase states here;
  - it breaks the next phase into task rows.
- A statement elsewhere in `docs/netlink/` that a task makes false is amended in that task's commit.

## Decision log

**2026-10-19:**
- **Class F is out of scope.** The ioctl, sysfs, `/proc`, syscall, cgroup and `bpf()` surfaces have no netlink message, so nlmon can't capture them and the pcap-based matrix can't compare them. If they are ever wanted, an strace capture (the RDMA route, `pkg/nlstrace`) is the starting point, as a separate plan.
- **Captures first.** The user directed that the corpus be completed before the parsers, and the parsers before goip, because committed testdata and parsers make the rest easier. The tiers are ordered C, then P, then G accordingly.
- **The universe is measured at the pin.** It is v7.1.0, not the 7.2 checkout. maddress is therefore class F until the pin bump.
- **The status lives in its own document.** It is split out of the plan the way [addr-write-path-status.md](addr-write-path-status.md) is. A phase is closed in its last task PR, not in a separate docs PR.
- **Capture modules are loaded late, by the drivers, not at boot.** A module that creates per-namespace fallback devices puts them in every namespace, including ones that already exist. Loading the tunnel modules at boot was measured to move goip0 from ifindex 3 to 10, which would rewrite every committed fixture (`nix/microvms/mkVm.nix:4034-4049`). C0-T02 therefore modprobes after every existing row is captured, as `capture-netlink-dumps.exp:775` already does for the tunnel modules.
- **C0-T01 fixes the nexthop floors it found.** The capture gate couldn't pass without the fix. Eight rows had a floor of 4 in namespaces whose nexthop table is empty, so every full `netlink-dump-capture` run ended `NLCAP_DRIVER_FAIL`. An empty table's dump is its request and NLMSG_DONE, so the floor there is 2 (`nh_floor`, `capture-netlink-dumps.exp`).
- **C0-T01 fixes the tier2 lint findings `main` carried.** lint-baseline is one of its gates, and `main` at `b7eec04d` failed it with 17 findings in `internal/goip` (V006). They were fixed in the code rather than baselined: `showObjects` is derived from the objects table (with an `alias` marker), the goiphttp registry defaults `object` to `path`, and the exhaustive, prealloc and unconvert sites were corrected (V007).
- **C0-T02 loads the genl and XFRM modules in one late step, shared by both drivers.** `nltopo::late_setup` runs after every existing row, into `late/`, so nothing already captured sees them. The list is `nltopo::late_modules`; the tunnel modules stay where they were, loaded before the dump driver's tunnel set. The crypto list is cbc(aes)+hmac(sha256) and rfc4106(gcm(aes)) ESP; C3 adds to it if its rows need more. Its sidecar says `loaded` or `builtin`, not raw `lsmod` output, because a built-in module is a pass that `lsmod` doesn't list.
- **C0 closed with C2 expanded.** C2's tasks were already named in the plan's table, so its range row became C2-T01 to C2-T08. C1 and C3 already had one row per task.
- **C0 reached `main` through a follow-up PR.** #266 and #267 were opened stacked, on `docs/goip-parity-gaps` and `goip-gaps/c0-t01`. They were merged after #265 without being retargeted, so they landed in those branches, and #268 brought `goip-gaps/c0-t01` into `main`. Task PRs are now opened against `main`.
- **C1-T01 has a SETNEIGHTBL row the plan did not name.** The kernel's `neightbl_set` refuses the table-wide thresholds (`thresh1`-`3`, `gc_int`) outside the initial namespace with ENOENT, and every capture runs in a namespace of its own. The accepted row therefore changes a per-device parameter (`dev d0 queue 64`), and `thresh1` is kept as a refused row, which records the refusal.
- **The C1-T01 netns rows add, use and delete their peer in one command.** `xtcp2-nlcap write` runs the command under `ip netns exec`, whose mount namespace is a slave of the root's. A peer that `ip netns add` makes there is a bind mount only that mount namespace sees, so a pre step cannot make it for the write, and a separate readback cannot see it. `netns_set` runs its `ip netns list-id` readback inside the command, and both rows delete the peer, which also removes `/run/netns/<peer>`.
- **The C1-T01 event rows' floors are two thirds of the first passing run** (14 of 21, 20 of 30), as `addr_monitor`'s are. The other floors are structural. The first run measured that `ip ntable` dumps the links before it writes (`ll_init_map`), even when it names no device, so every ntable row's floor is 4.
- **From C1-T02, tasks are committed without a PR each.** The per-task PR cycle was slow, so each task is committed to the working branch once its gates pass, with its checklist row and ledger rows in the same commit. Pushing and opening a PR happen when asked.
- **C1-T02 splits the empty route flush in two.** A flush of a table that was never made is a dump the kernel refuses with ENOENT ("FIB table does not exist", in NLMSG_DONE), rc 2. The boundary row the plan asked for, a flush with nothing to delete, makes table 100 and empties it first (a table outlives its last route), and the never-made table is kept as the refused row `route_flush_no_table`.
- **C1-T02 records that `ip rule restore` duplicates rules.** Restore sends NEWRULE with `NLM_F_CREATE` and no `NLM_F_EXCL`, and the kernel only refuses a duplicate rule under `NLM_F_EXCL`. Restoring into a namespace that already has the default rules therefore gives main and default twice, and the saved pref 0 rule, whose message has no `FRA_PRIORITY`, comes back at an auto-assigned 32765. The row keeps that behavior and `TestRtnlWriteCorpusShapes` pins it. goip's restore (G3) should match `ip`, not correct it.
- **C1-T02 leaves DELNEXTHOPBUCKET (117) at 0.** The kernel registers no handler for it and never sends it (`net/ipv4/nexthop.c` emits only NEWNEXTHOPBUCKET), so there are no bytes to capture. C4's universe test lists it as an exclusion.
- **C1-T03 keeps an smcrouted daemon running while it reads.** The kernel drops an (S,G) cache entry when the socket that added it closes, so a one-shot `smcroutectl` or `ip` cannot leave one to read. `xtcp2-nlcap mroute-start` runs `smcrouted` in the namespace until `mroute-stop`, and its VIF devices are veths, since a dummy has no `IFF_MULTICAST`.
- **C1-T03 captures only the netlink half of `tunnel show` and `tuntap show`.** Both list links by dump, then read each tunnel's parameters through `SIOCGETTUNNEL` and each tap's flags from sysfs, neither of which nlmon sees. The pcaps are committed for the dump; the ioctl and sysfs halves stay in [class F](goip-parity-gaps.md#f-not-netlink-outside-pcap-parity), and the topology sidecar records the note.
- **C1-T04's event rows are in the link-write corpus, not the nlmon-capture flavor.** The plan named `microvm-x86_64-nlmon-capture`, whose oneshot captures one whole boot. The C1-T01 event-row form (`xtcp2-nl-ipmon` with a canary multicast join, one row per pcap with its topology, stdout and rc) gives each event its own fixture, and the driver already gates floors and statuses.
- **The NEWPREFIX trigger is a router advertisement sent inside the namespace.** `xtcp2-nl-ra` sends from `r0p` to its veth peer `r0`. The kernel drops an RA whose source is one of its own addresses unless `accept_ra_from_local` is 1, and both ends are in the namespace; `r0` also needs `accept_ra` 2 in case forwarding is on. Multicast loopback is off, so `r0p` does not receive its own RA and notify a second NEWPREFIX.
- **`ip` prints no `onlink` or `autoconf` for a received RA, and goip should match.** The kernel copies the option's flags byte into `prefix_flags` as it is on the wire (L 0x80, A 0x40), but `ip/ipprefix.c` tests `IF_PREFIX_ONLINK` (0x01) and `IF_PREFIX_AUTOCONF` (0x02). The output also has no space before `dev`. `TestRtnlMonitorCorpus` pins both.
- **`ip monitor all` takes no `maddress`.** Any object named on the command line replaces the default set, so `all maddress` is maddress alone. `all` already includes it, and it is the only group the canary needs.
- **The NEWNEXTHOP notification has `NLM_F_REQUEST` set.** `nexthop_notify` copies the request's `nlmsg_flags` into its event (`net/ipv4/nexthop.c:1091`), so a listener can't tell a nexthop event from a request by its flags alone. The test tells them apart by `nlmsg_pid`, which `ip` sends as 0 and the kernel sets to the requester's port. goip's event decoding (G1 on) must not filter on `NLM_F_REQUEST`.
- **C1 closed without expanding C2.** C2's tasks were already one row each (C0's close).
- **C2-T01 makes its tcp_metrics entries over local addresses, not a veth pair.** The kernel saves an entry when a connection with an RTT sample closes, whatever device carried it, so two addresses on a dummy, with the namespace's `lo` carrying the traffic, give the same four entries (one per end per family) with less to build. The genl rows run after late setup, as every row added since C0-T02 does.
- **`ip tcp_metrics` skips the word after an address, and goip need not.** The argument loop in `ip/tcp_metrics.c` (v7.1.0) advances in its body and again in its `for`, so `show address A src B` reads B as a second address and exits 255 (`either "address" is duplicate`), while `show src B address A` works. The `src` rows put `src` first. A goip `tcp_metrics` parity row should use that order.
- **`prefix_event`'s floor is 11, not 18.** C1-T04 set it to two thirds of a run whose canary had gone round twice (27 datagrams). With one canary cycle the row is 17, which V043 and V044 measured three times, so 18 failed every run. The committed fixture, from the two-cycle run, stays.
- **A walking flush sends its DELs without `NLM_F_ACK`.** `flush <prefix>` and `-6 flush` batch one DEL per match into a datagram with no ACK asked for, then dump again; `flush all` with no family is a single DEL that asks for one. The test pins both.
- **`ip sr hmac set` gets its secret from stdin under `setsid`.** It reads the secret with `getpass(3)`, which uses `/dev/tty` whenever the process has a controlling terminal, so a pipe alone is ignored under an interactive driver. `setsid -w` takes the terminal away; `getpass` then reads stdin and prompts on stderr, which is why every set row's `ip.err` holds the prompt.
- **`ip sr`'s refused writes exit 1, and goip should match.** `ip/ipseg6.c` returns -1 from a failed SETHMAC or SET_TUNSRC, so `ip` exits 1, where the rtnetlink and tcp_metrics commands exit 2 for a refused request. The two refused rows pin rc 1.
- **`ip` shows at most 63 bytes of an HMAC secret, and goip should match.** The kernel takes and returns up to 64 (`SEG6_HMAC_SECRET_LEN`), but `ip/ipseg6.c` copies the secret into a 64-byte string buffer, so it prints 63 and warns `HMAC secret length 64 > 63, truncated` on stderr. `sr_hmac_show_64` was added for this.
- **`ip ioam monitor` is captured by sending the kernel a traced packet.** `IOAM6_EVENT_TRACE` is sent by `ipv6_hop_ioam` (`net/ipv6/exthdrs.c`) when an IPv6 packet whose hop-by-hop header holds a 4n-aligned IOAM pre-allocated trace option arrives on a device with `ioam6_enabled`, for a namespace the kernel knows, while someone listens. The ioam6 lwtunnel only inserts that option, so its absence from the guest kernel (`IPV6_IOAM6_LWTUNNEL`) doesn't matter: `xtcp2-nl-ioam` writes the option itself with `IPV6_HOPOPTS` on a UDP socket to `::1`. That needs CAP_NET_RAW, which the check sandbox lacks, so the helper's send is exercised in the VM, and the sandbox pins its bytes and its refusal. A first draft of this task wrongly read the lwtunnel as the event's only source and left the monitor out; reading `exthdrs.c` corrected it before the commit. Two rows pin when no event comes: an unknown namespace, and `ioam6_enabled` off.
- **The kernel hides IOAM6 data equal to its "unavailable" value, and goip should print what the dump holds.** A namespace with no data is stored with all ones, and the dump leaves an all-ones value out, so `data 0xffffffff wide ffffffffffffffff` reads back as no data. The kernel also pads schema data with zeros to a multiple of 4, so 5 bytes read back as 8. The test pins both.
- **`ip mptcp`'s refused requests exit 2, and its refused arguments 255, and goip should match.** `ip/ipmptcp.c` returns -2 when the kernel refuses, as tcp_metrics does. It checks some arguments itself after the family lookup: a port without `signal` is `invarg`, exit 255, with nothing sent. The row pins both the status and the message.
- **MPTCP_PM_SUBFLOWS_MAX is 8 in 7.1 and 64 from 7.2, and the rows pin 7.1's.** `limits set subflows 9` is refused on the guest's 7.1.4 (V059); the kernel tree read for this task (7.3-rc7) has 64, from "mptcp: pm: in-kernel: increase all limits to 64". A pin bump past 7.1 moves the boundary rows.
- **The mptcp monitor rows pin the events from the path manager's own listener and from one connection; SF_PRIO, ANNOUNCED and REMOVED are not captured.** Those need a backup change on a live subflow, or a peer announcing or withdrawing an address, which means holding a connection open across commands, or two path managers, in one namespace. Both ends of the connection share the namespace's endpoints, so the server's path manager also tries a subflow back to the client's ephemeral port and logs an SF_CLOSED with ECONNREFUSED; the test pins it. The userspace path manager's commands (ANNOUNCE, REMOVE, SUBFLOW_CREATE, SUBFLOW_DESTROY) are not `ip` commands, so they are outside the universe.
- **`ip fou` sends an empty ADD when it refuses its own arguments, and goip should not copy that.** `fou_parse_opt` prints `fou: missing port` or `fou: must set ipproto or gue` and returns -1, but `do_add` ignores the return and sends the request anyway, with no attribute, since the complaint comes before the first one is added. The kernel refuses it with `EINVAL` (no type), so `ip` prints its own complaint and then `RTNETLINK answers: Invalid argument`, and exits 2 (`fou_add_no_port`, `fou_add_no_type`). goip should refuse such arguments without a request; the parity comparison of these two rows is on stderr's first line and the rc, not on the wire.
- **`ip fou`'s own refusals exit 255 or 1, and goip should match.** Port 0 is `invarg` (255). An unknown dev is `exit(EXIT_FAILURE)` (1), and `show` with an argument returns -1 from `do_show`, which `ip` negates to 1. Each is after the family lookup, with nothing more sent.
- **A fou GET that is not a dump, and `FOU_ATTR_REMCSUM_NOPARTIAL`, are not captured.** `ip/ipfou.c` sends GET only as a dump, and has no keyword for the flag, so neither is reachable from `ip`; the kernel's `fou_nl_get_doit` and the flag's parse path stay without bytes. The corner row in `TestGenlFouCorpus` pins that no row sends either.
- **`ip ila` sends an empty ADD when it refuses its own arguments, and the kernel takes it.** As with fou, `ila_parse_opt`'s -1 is ignored, so `ip ila add loc_match X` prints `ila: missing locator` and sends an ADD with no attribute. Unlike fou's, the kernel accepts it, as a mapping of locator 0 to locator 0 with its default csum-mode and ident-type, and `ip` exits 0 (`ila_add_no_loc`). By the code, a bad locator, csum-mode, ident-type or dev does the same; those are not captured. goip should refuse such arguments without a request rather than create the zero mapping; how the parity row compares a deliberate difference is for G to decide.
- **Every `ip ila del` exits 0, and goip should match.** `ila_xlat_nl_cmd_del_mapping` returns 0 whatever `ila_del_mapping` found, so a delete of a mapping that is not there, or one that misses on the dev, is ACKed (`ila_del_missing`, `ila_del_nodev_of_dev`).
- **`ip ila show` prints csum-mode and ident-type with nothing between them, and goip should match it.** `print_ila_mapping` prints each with a bare `%s`, so a line ends `no-actionuse-format`. The parity matrix compares text, so goip prints the same; the JSON output keeps them as separate keys.
- **An ila GET that is not a dump, and FLUSH, are not captured.** `ip/ipila.c` sends GET only as a dump and has no flush command, so `ila_xlat_nl_cmd_get_mapping` and `ila_xlat_nl_cmd_flush` stay without bytes. The corner row in `TestGenlIlaCorpus` pins that no row sends either.
- **A duplicate L2TPv3 session id in a UDP tunnel is taken, even in the same tunnel, and the dump then shows only one of the two.** `l2tp_session_register` puts a UDP tunnel's duplicate on a collision list, refusing it (`EEXIST`) only when the existing session is in an IP-encap tunnel. `l2tp_v3_session_get_next` assumes one session per id per tunnel and stops at the first hash match, the newer, so `ip l2tp show session` lists `l2tpeth1` and not `l2tpeth0` (`l2tp_session_add_dup`, `l2tp_session_add_dup_ip`). The fixtures pin what kernel 7.1.4 does; goip should match the dump it gets, not the sessions it made.
- **`ip l2tp show` with ids is a dump, and goip should match it.** `ip/ipl2tp.c` always sends GET with `NLM_F_DUMP` and puts the ids in the request; the kernel's dump handlers do not read them, and `ip` prints every tunnel or session that comes back. A GET that is not a dump (`l2tp_nl_cmd_tunnel_get`, `l2tp_nl_cmd_session_get`) is therefore never sent, and has no bytes.
- **TUNNEL_MODIFY, SESSION_MODIFY and NOOP are not captured.** `ip l2tp` has no command that sends them. The corner row in `TestGenlL2tpCorpus` pins that no row does.
- **l2tp's multicast notifications are not captured.** The kernel sends a copy of each create and delete to the `l2tp` multicast group (`l2tp_tunnel_notify`, `l2tp_session_notify`), but only to listeners, and no row opens one, as `ip` has no l2tp monitor. A row with a listener is G's to add, if goip grows a monitor.
- **`ip macsec show DEV` is a dump, and goip should match it.** `ip/ipmacsec.c` sends GET_TXSC only with `NLM_F_DUMP` and prints the SecY whose ifindex matches, so `show macsec1` gets every SecY back (`macsec_show_dev`). macsec's GET_TXSC has no handler for a GET that is not a dump.
- **The kernel returns a key id but never a key, and an SSCI but never a salt.** `dump_secy` writes `MACSEC_SA_ATTR_KEYID` and, on an XPN SecY, `MACSEC_SA_ATTR_SSCI`, and leaves the key and salt out, so `ip` prints the key id after `key`. goip prints what the dump holds.
- **A SecY's `oper` follows its encoding SA, and starts true.** `macsec_newlink` sets a new SecY operational before it has any SA, and an UPD_TXSA of the encoding SA sets operational to the SA's ACTIVE, so `set … tx sa 0 … off` reads back OPER 0 (`macsec_txsa_set`). `ip` does not print it; the test pins it.
- **`ip macsec`'s own refusals exit 1 or 255, and goip should match.** An SA with no key or no packet number, or a `set` with a key, fails `check_sa_args` and an unknown dev the dev lookup, each returning -1 (exit 1). SA number 4 is `invarg` (255). Each is after the family lookup, with nothing more sent to macsec.
- **`ip macsec` sends a salt and an SSCI only with `xpn`.** With `pn` the two words are parsed and dropped, so the 4-byte packet number on an XPN SecY reaches the kernel alone, which refuses it with EINVAL for its length (`macsec_xpn_txsa_pn32`).
- **No accepted offload mode change is captured.** `offload mac` and `offload phy` need a device with MACsec offload ops, and `d0` (a dummy) has none, so the kernel refuses `mac` (EOPNOTSUPP); `offload off` on a SecY already off is ACKed with nothing to change. Both send UPD_OFFLOAD, so the command has bytes; a device that takes the mode is a later task's, if goip needs it. macsec has no multicast group, so there are no notifications to capture.
- **`mptcp_monitor_conn`'s SF_CLOSED is a race.** V079's run closed the connection before the server's path manager logged its refused subflow back to the client, so it had 16 messages where the committed fixture has 17. The fixture, which has the event, stays; the C2-T04 decision that the server "logs an SF_CLOSED with ECONNREFUSED" holds for that fixture, not for every run, and the row's floor does not depend on it.
- **C2 closed without expanding C3.** C3's tasks were already one row each.
- **`ip xfrm state`'s own refusals send nothing and exit 1.** `ip/xfrm_state.c` checks its arguments (an ESP SA with no algorithm, `min` over `max`) before `rtnl_open_byproto`, unlike the genl tools, which have looked up their family first; the kernel's refusals exit 2. goip should match both.
- **allocspi asks for one SPI.** With a range the kernel picks the SPI at random, so the larval state would differ on every run; `min 0x200 max 0x200` keeps the fixture repeatable, and `allocspi_taken` covers a range with nothing free.
- **The time an SA was added is not pinned.** `ip -s` prints it and `curlft` carries it, so `TestXfrmStateCorpus` checks the lifetime limits and the byte and packet counts, not the add time.
- **XFRM returns keys.** Unlike macsec, a GETSA or dump answer carries the SA's keys, so the corpus's keys are fixed test values (every byte the same) and never anything real.

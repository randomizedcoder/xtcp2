# genl clones (devlink, vdpa, fou, mptcp, tipc): implementation status

**Last updated:** 2026-11-22

**Summary:**
- The design and task plan are in [genl-clones.md](genl-clones.md). This document tracks
  progress against them. The arc follows the closed `ip`-clone work
  ([goip-parity-next.md](goip-parity-next.md)), whose ledger ran to V078; this arc's
  ledger starts at **V079**.
- The arc did three increments — **devlink**, **vdpa**, **fou** — each
  captures → parser → table tests → read-only render clone, each continuing the iproute2
  bug hunt (recorded only). A fourth, **mptcp**, was added after they closed.
- **Increment 1 (devlink): complete.** 1C captured 22 rows (ten read-only dumps ×
  plain/`-j` + two negatives), serial with a fixed netdevsim bus id 0, two boots
  byte-identical (V079); 1P added `ParseDevlink` + table/fuzz tests + the O3/O4 corpus,
  classifying by attribute presence since the kernel renumbers the command enum (V080);
  1R added the `godevlink` render clone replaying the ws pcap byte-exact (V081); 1B
  recorded two `devlink/devlink.c` print-path bugs (DOC026).
- **Increment 2 (vdpa): done.** 2C captured 20 rows (seven read-only shows ×
  plain/`-j` + six negatives) on a workbench kernel with `vdpa_sim_net`, two boots
  identical (V082). The vdpa genl family answers only in init_net (`netnsok` false), so
  the workbench gained an init-namespace row mode (`initns`, helper `ns-init`). 2P added
  `ParseVdpa` + `BuildGetVdpaRequest`, table/fuzz tests and an O3 that rebuilds every
  captured request byte for byte (V083). 2R added the `govdpa` render clone, which
  replays all 20 rows byte-exact (V084). 2B recorded eight `vdpa/vdpa.c` print/argument
  findings, headed by the vstats `queue_type` mislabel (DOC027).
- **Increment 3 (fou): done.** 3C captured 13 rows (`ip fou show` over five
  namespace fixtures × plain/`-j`, plus three negatives) on the base workbench kernel,
  whose `fou` module is already present (no kernel patch needed, unlike vdpa). fou's genl
  family is `netnsok=true` and per-netns, so each row runs in its own fresh namespace with
  its own `ip fou add` setup; the dump sees only those ports. Two fresh boots are
  byte-identical (V085). 3P added `BuildGetFOURequest`, a fuzz and an O3/O4 corpus test
  that rebuilds every captured request byte for byte; the parser (`xtcpnl_fou.go`) already
  decoded the full attribute set (V086). 3R added the `gofou` render clone, which replays
  all 13 rows byte-exact (V087). 3B recorded three `ip/ipfou.c` print-path findings, headed
  by a dropped `REMCSUM_NOPARTIAL` attribute (DOC028). **Increment 3 is done, and with it
  the whole three-family arc.**
- **Pre-push gates and push (GATE-1): done.** Full `go test ./...`, `test-go-race` and
  `lint-baseline` pass after a lint fix in the gofou tests; `goip/genl-clones` is pushed,
  with no PR yet (V088).
- **Increment 4 (mptcp): done.** The user chose `ip mptcp` (genl `mptcp_pm`). 4C
  captured 26 rows: nine read-only endpoint/limits fixtures × plain/`-j`, plus eight
  negatives. MPTCP is built in, so the workbench kernel needed nothing. ip's endpoint
  paths also dump links on rtnetlink (`ll_init_map`) to name a `dev`, so the rows capture
  on a new `generic+route` protocol. Two fresh boots are byte-identical (V089).
  `goip` already clones `ip mptcp` (and `ip fou`, which `gofou` duplicates), so with the
  user the increment was re-scoped: no `gomptcp`; 4P adds the fuzz target and O3/O4 over
  the corpus (V090), and 4R holds goip to it: all 26 rows replay through goip with ip's
  stdout and exit status, and ip's genl and route requests, with no goip change needed
  (V091). 4B recorded seven `ip/ipmptcp.c` findings, headed by `-j limits show`
  printing text (DOC029). **Increment 4 is done.**
- **gofou retired into goip: done.** `gofou` duplicated goip's `obj_fou.go`, so with
  the user it was folded in. `internal/goip/ws_fou_test.go` now holds goip to all 13
  fou ws rows: ip's stdout, exit status and genl exchanges, with no goip change
  needed. The ws replay helpers are now shared by fou and mptcp (`ws_genl_test.go`).
  `cmd/gofou`, `internal/gofou` and its nix binary entry are deleted (V092).
- **Increment 5 (tipc): in progress.** The user chose `tipc` (genl `TIPCv2`), a
  standalone CLI goip does not clone. 5C captured 93 rows: 40 read-only commands over
  six namespace fixtures, each plain and `-j`, plus 13 negatives. The workbench kernel
  needed nothing. Two fresh boots agree except where TIPC is random (socket ports) or
  timed (the peer link's counters) (V093). The capture already turned up a crash:
  `tipc -j link get broadcast` dies of SIGSEGV (to be written up in 5B). 5P added
  `ParseTIPC`, `BuildTIPCRequest` and `BuildTIPCFamilyRequest`, table and fuzz tests,
  and an O3/O4 test. O3 rebuilds all 193 requests the rows sent, byte for byte: the
  family lookups, and the follow-up queries `socket list` and `link monitor list` make
  from their replies. It also decodes all 104 replies (V094). 5R added the `gotipc`
  render clone, which replays all 93 rows byte for byte: stdout, stderr and exit status,
  including the crash row's 139 (V095).

  append-only, continuing the shared sequence (the `ip`-clone arc ended at V078).

  G6-T05), which the plan missed for 3R: `gofou` duplicates it. The user chose to build
  no `gomptcp` and instead hold goip to the new ws corpus (4P fuzz + O3/O4, 4R goip
  replay of all 26 rows, 4B audit). At first `gofou` stayed, with the overlap recorded
  here; see the next entry.
- **2026-11-22 — gofou retired into goip.** After the push, the user chose to resolve
  the overlap by retiring `gofou` rather than keeping two `ip fou` clones. goip already
  reproduces all 13 fou ws rows and also covers add/del. `ws_fou_test.go` holds goip to
  the corpus gofou was built on, and gofou is deleted (V092).
- **2026-11-22 — increment 5 is tipc.** The user chose `tipc` next. It is a standalone
  iproute2 CLI with no goip object, so it gets the full rhythm and a clone, `gotipc`.
- **2026-11-22 — tipc's two-boot rule allows named rows to differ.** TIPC picks socket
  ports at random, and the peer link's counters depend on timing, so those replies
  cannot be identical across boots. Fixing ports would need a kernel change. The rule
  for this space: rc, stderr, message types and flags are identical on every row;
  stdout and request bodies too, except on the rows named in V093. Replay parity is
  unaffected, since the clone replays the batch of record.
- **2026-11-22 — mptcp rows capture generic+route.** ip names an endpoint's dev from its
  own RTM_GETLINK dump (`ll_init_map`), on rtnetlink. Three alternatives were rejected: a
  `generic`-only capture plus a dev-name sidecar, a readback `ip link` capture, and a
  clone that never prints dev. None replays what ip sent, and byte-for-byte parity is
  about what was sent. The helper filter became an expression so one row can keep two
  protocols. The change is additive: existing protocols are untouched.

- **2026-11-13 — families and the netdev swap.** Three increments: devlink, vdpa, fou.
  `netdev` genl was dropped (no userspace CLI — only the kernel's unpackaged `tools/net/ynl`),
  and `fou` swapped in (genl family with the `ip fou` CLI). `gtp` is out for the same reason
  as netdev. See [genl-clones.md](genl-clones.md).
- **2026-11-13 — classify by attribute, not command number.** The devlink
  `DEVLINK_CMD` enum is renumbered between kernels (commands inserted mid-enum
  shift later ones), so the capture kernel's wire command for a dump differs
  from the upstream number — `resource show` is 36 here, 40 upstream; the ten
  reply commands shift similarly. The `DEVLINK_ATTR_*` tree, by contrast, is
  append-only and stable. `ParseDevlink` therefore selects its one typed
  section by the marker attribute's presence, and the O3/O4 corpus test ties
  each row to its operation by the decoded reply **section** (keyed off the
  `words` axis), never by the request command number. The `cmd` axis stays as
  the documented upstream reference only.
- **2026-11-13 — `nosuch` is ack-then-fail, not an iproute2 refusal.** `devlink
  nosuch show` resolves the family (one acknowledged `CTRL_CMD_GETFAMILY`)
  before its command table rejects the object, so no devlink-family request is
  sent but one control request was — `ack-then-fail` by the ws taxonomy, not
  `iproute2` (which needs zero requests). V079 mislabeled it; corrected in 1P.
- **2026-11-14 — vdpa rows run in init_net.** `vdpa_nl_family.netnsok` is false, so vdpa
  cannot be captured from the per-row namespace every other space uses. Rather than a
  bespoke capture path, the batch runner gained an `initns` row mode. The helper binds
  init_net as a named namespace (`ns-init`), and every existing primitive (`write`,
  `capio`, the pre steps) runs unchanged through `ip netns exec`. Isolation is replaced by
  the protocol filter plus a quiet guest, and the two-boot agreement is the check. An
  `initns` row must be serial.
- **2026-11-14 — vdpa binds virtio_vdpa, with its netdev unmanaged.** vstats needs completed
  feature negotiation (EAGAIN otherwise), which takes a bound virtio driver. The driver's
  `eth0` must not be brought up, or networkd traffic through the simulator's loopback makes
  the counters timing-dependent, so a runtime networkd file marks its fixed MAC `Unmanaged`.
  The no-driver EAGAIN refusal is not captured, since a batch has one module state.
- **2026-11-13 — devlink capture determinism.** `devlink dev show` prints the netdevsim
  bus handle and an `index` counter, both of which vary with device-creation order. Fixed
  by a **fixed bus id 0** in the pre step plus running all devlink rows **serial**, so the
  order (and the counter) is deterministic. Two fresh boots then capture byte-identical
  output; no normalization pass is needed.

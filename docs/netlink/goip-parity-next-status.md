## Update rules

- States are `not started`, `in progress`, `blocked`, `done` or `deferred`. There are no percentages.
- A task is `done` only when its gates have passed and the evidence is in the [ledger](#verification-ledger).
- Evidence IDs (`V###` for code and VM runs, `DOC###` for docs) are immutable and append-only.
- Task IDs (`NCn-Tmm`, `NXn-Tmm`) are never renumbered.

## Decision log

- **Captures first, at both iproute2 versions.** The 2026-11-09 assessment went from source reading to goip tasks. Planning starts from captures instead: the workbench, generated rows, and pcaps with their `ip` commands, as the earlier plans did.
- **7.3.0 is captured without moving the pin.** The workbench takes `--ip <store path>`, and `iproute2_7_3_0` is a capture-only package. So 7.2.0 and 7.3.0 rows come from the same guest and kernel, and the diff between them is `ip`'s alone. The pin moves in Tier G's NX4.
- **The version is recorded in each row's `cmd.json`.** `env.iproute2` is taken from `ip -V` on the PATH the row runs with, so it already says 7.3.0 under `--ip`. No separate `ip_version` sidecar is needed.
- **`^out` for the store path.** `iproute2_7_3_0` has a `man` output too, so a bare `--print-out-paths` prints two paths. The usage text names `'.#iproute2_7_3_0^out'`.
- **New captures go under `testdata/7_3_1/`.** The workbench boots kernel 7.3.1 now, and the corpus directory names the kernel that answered. The O3 tests read every `testdata/*/ws`. O5 (`TestWsGoipDifferential`) still reads only `7_3_0/ws`; NX2 widens it. The `linkattr` rows recaptured at 7.3.1 matched the 7.3.0 corpus byte for byte, so the old rows stay where they are.
- **`linkns` is a space of its own, with named rows.** Adding to `linkattr`'s axes would renumber its committed `ec`/`ng` rows. And a create and a real move don't fit `linkattr`'s O3 model of a set on d0.
- **MPLS rows set `platform_labels` through `/proc/sys`.** A pre step runs in the row's namespace, so the write is per row and needs no `sysctl` binary.
- **`ParseNewRoute` is not changed for an IP route's RTA_NEWDST.** `ip route add … as 200` sends one, and the kernel ignores it, so no dump carries it. O3 reads that request raw.
- **NC3-T01's findings.** Between 7.2.0 and 7.3.0, ip changed only `dst_port` and `fdb `'s trailing space in these 17 families. No request byte changed in any other row.
  - `lacp_strict` didn't appear, because no replayed row makes a bond.
  - No rc changed under the strict `ll_addr_a2n`, because no row uses a malformed lladdr.
  - Both are left to NC3-T02's `v730` rows.
  - `ss` 7.3.0 dropped DCCP (3c0b939e): its usage text no longer lists it. No replayed `ss` row asks for DCCP sockets. Kernel 7.3.1 accepts `NHA_DST_PORT`: `dev d0 dst_port 4789` is refused by the kernel ("Destination port can only be set on fdb nexthops that have a gateway"), not by `ip`.
- **A repeat run is verdiff's noise baseline.** Readbacks carry timers, socket order and padding that differ run to run, so a 7.2.0 repeat is diffed too, and only what it doesn't show is ip's. One repeat misses some noise by chance (3 timers, 12 orderings), so each remaining line was read.
- **`v730` is a family of named rows, written once per version.** The matrix spaces have one expectation per row, but here the version decides it. Two rows files with the same ids let a capture at each version pair up in `verdiff`.
- **The strict `ll_addr_a2n` regresses nothing a script would see in rc.** It does print a spurious `"bcqueuelen" is invalid lladdr.` when `macaddr set` is followed by another keyword. Recorded only: nothing goes to netdev.
- **ip 7.3.0's `maddress show dev nosuch` ignores the kernel's ENODEV.** It exits 0 with no output, as 7.2.0 did from procfs. The oracle's `kernel-ignored` names it. goip's `maddress` matches the rc and the silence (NX4c, V043).
- **The pin moves to 7.3.0 for the parity guest only.** Overriding `pkgs.iproute2` would rebuild everything that depends on it, so 7.3.0 is a package of its own (`nix/iproute2-7-3-0.nix`), shared by the workbench's `--ip` and the goip-parity guest, where `hiPrio` puts it ahead of the 7.2.0 other packages still pull in. Drop it when nixpkgs reaches 7.3.0 (NX4d, V044).
- **The maddress rows gated on section runs, not the ungated list.** As the nexthop selector rows at 7.2.0: two clean section runs at the floors they keep, then gated with `earned` naming the runs (V044).
- **The `maddress` requests are 24 bytes, not the 152 the plan said:** a header and an `ifaddrmsg`, one dump per family.
- **The bare `ip stats show` order is pinned from the captures.** ip prints a device's groups in the order of its sorted descriptor pointers, not the table's. At 7.2.0 on this build, that is the same 13-leaf order on every device, topology and boot (V025). goip's NX5 renders in `wsStatsOrder`. A different `ip` build could print another order, so NX4's move to 7.3.0 rechecks it.
- **Tier P drops the CPU_HIT and L3_STATS decoders.** No workbench device reports either body, so their tests would only read hand-built bytes. They wait for a capture, from hardware or netdevsim.
- **`RTA_TTL_PROPAGATE` reads like the other route scalars.** The plan had a u32 payload as an error. `setRouteAttr`'s scalars never fail: an empty payload is dropped, and a longer one is read from its first byte, as `rta_getattr_u8` in ip reads it. A u32 then decodes the same as ip prints it. The plan's NP2 table now says so, and NP3's `IFLA_OVPN_MODE` follows the same rule (`ovpn_print_opt` reads it the same way).
- **A short `MPLS_STATS_LINK` keeps the record.** The plan had it as an error. `ParseNewStats` keeps a malformed afstats member and marks `AfSpecMalformed`, as it does for the nest's walk, so the short link does the same and goip can decline it. ip reads the struct unchecked.
- **`ip -j link afstats` prints invalid JSON at 7.2.0:** members with no object around them, `["ifindex":1,…]`. The corpus test skips it. Recorded only: nothing goes to netdev.
- **`netns` with `link-netnsid` sends without a `setns`.** When both are given, ip `setns`es into the target namespace to open a second rtnetlink socket there, and switches back (ip/iplink.c:1317). That socket serves only `link-netns` and a `link` device's lookup; the request still goes on ip's first socket, so goip, which opens none, sends the same bytes. The bytes are the same, but a file that isn't a namespace makes ip refuse with "Cannot set namespace", where goip sends and the kernel refuses.
- **The VM matrix has no pid form of `netns`.** The only pid the VM can name ahead of the row is init's, and moving d0 there keeps it in the root namespace. O5 covers the pid forms offline.
- **The descriptor is an accepted divergence, as for `netns set`.** ip sends fd 4, goip whatever slot is free (6 in the VM). The kernel resolves either to the same namespace.
- **NX5 splits in three.** NX5a is `ip stats` (ipstats.c); NX5b is `ip link afstats` and NX5c `ip link xstats`, which are iplink.c's own loops over the same bodies. `render/bridge_xstats.go`'s views stay until NX5c moves `link xstats` onto the Printer callbacks (V046).
- **`ip stats` renders through a json_print.c port, not view structs.** ipstats.c interleaves `print_*` calls whose text and JSON differ in order and in what they print, so goip replays the calls on a `render.Printer` that writes one or the other. `IfStatsView` and its tests are gone; `IfStatsHwSInfoText` stays for the monitor (V046).
- **-EINVAL is its own exit code.** ipstats.c returns -EINVAL from main, which the shell sees as 22; goip has `ExitEINVAL`, and `ErrStatsInval` maps to it. `ErrStatsUsage` is the 255 of `NEXT_ARG`, `duparg2` and `invarg` (V046).
- **`dev nosuch` is the kernel's ENODEV, as ip reads it.** ll_name_to_index turns the ENODEV into index 0 and ip prints `Cannot find device`, exit 1; goip does the same, and the corpus row's pcap carries the ENODEV, so the replay exits 1 too. A by-name get that gets no answer at all is a separate failure, `stats show: cannot find device`, which ip has no counterpart for (V046).
- **`ip link afstats` exits 0 whatever happens after its arguments.** do_iplink calls iplink_afstats and returns 0 without looking (ip/iplink.c:1842-1845), so `dev nosuch` prints `Device "nosuch" does not exist.` and exits 0, and so does a dump that fails. A script can't tell either from a device with no AF stats. goip matches the rc. An iproute2 finding, recorded here only: nothing goes to netdev (V047).
- **NX5b's VM rows gate with NX5c's.** Both tasks' rows are in the `link` section (about 800 rows), so one pair of `--section link` runs after NX5c gates them all, rather than two pairs. The VM can't show an MPLS body here: these rows run before any row loads `mpls_router`, so the VM's afstats are empty, and only the corpus shows ip's MPLS body (V047).
- **The last view structs go with NX5c.** `link xstats` prints through `render.Printer` as `ip stats` and `link afstats` do, so `render/bridge_xstats.go` and `render/link_xstats.go` and their tests are deleted (V048).
- **NX3 is two tasks.** `route get` prints its reply with print_route, which for AF_MPLS is the same render `route show` needs. So NX3a is the writes, and NX3b is get and show together.
- **The MPLS VM rows spell `-f mpls` as `-M`.** A row's section is its first word that isn't an option, so `-f mpls route …` would be a section called `mpls`. `-M` sets the same preferred_family and sends the same bytes.
- **`mpls_router` loads in a row's Setup, last among the route rows.** goip-parity.exp's `setup_step` gains `modules NAME...`. A module is kernel-wide and stays loaded, and it gives every device an AF_MPLS netconf entry and afstats. After the MPLS rows come only genl and XFRM rows, which read neither.
- **goip's route invargs exit 1, ip's 255.** Every route write refusal is ErrInvalidArgument, exit 1; ip's invarg exits -1 and get_addr exits 1. It shows on 4 mpls rows (`ng-013`, `ng-018`, `ng-019`, `ttl-after-hops`) and on every other route invarg. A write row's goip must exit 0 to be compared, so no VM row can see it. Recorded only.
- **`route_write_replace_nfs` can fail on ip's stack byte.** In NX3a's second route run, ip sent `cubic\0p\0\0` in RTAX_CC_ALGO and goip `cubic\0\0\0\0`: `rta_addattr_l`'s uninitialised padding ([the upstream report](upstream/iproute2-rta-addattr-uninit-padding.md)). nlparity's `samePastPadding` ignores padding only in an `NLA_F_NESTED` payload, and ip sends RTA_METRICS without the flag, so a gated row fails whenever the byte isn't zero. O5 already zeroes it (`wsO5ZeroMetricsPad`). Closing the gap in nlparity is a follow-up, not NX3's. NF1 closed it (V052).
- **NX4 is four tasks.** NX4a is the render and parse knobs, NX4b the write keywords (`dst_port`, `lacp_strict`, seg6 `lookup`, ovpn `mode`) and ovpn's `-d`, NX4c `maddress show` over netlink, and NX4d the pin itself, the matrix under 7.3.0 and a full run.
- **Three knobs, not four.** The plan named `RenderNhFdbSpace`. ad2b2d95 made both `fdb `'s space and the `dst_port` token, so one knob, `RenderNhDstPort`, covers the commit. The knobs default to 7.3.0, as `RenderQlenZero` did at 7.2.0, and each test package's TestMain sets the release its corpora ran.
- **goip's `route show` prints no encap.** At 7.3.0 the six seg6 rows' readbacks show `2001:db8:2::/64  encap seg6 … lookup 100 dev d0`; goip prints the route without the encap, as for every lwt encap (`render/route.go`, "What this renderer does not print"). It predates 7.3.0 and isn't NX4's. `TestWsV730Readbacks` names the six. Rendering `RTA_ENCAP` is a follow-up. NX6a renders mpls and seg6 (V053); the other types and `nexthop show` remain.
- **No iproute2 bug found in the 7.2.0 → 7.3.0 diff.** 0067cbc8, the bond partner-state width fix reported from this work, is in 7.3.0. 7.2.0's `ll_addr_a2n` returned len+1 for too many parts and let its caller copy past the buffer; 5faf18f6 refuses them, so that bug is gone too.
- **goip's 7.3.0 keyword invargs exit 1, ip's 255.** `dst_port 65536`, ovpn `mode x` and `lacp_strict 1` print ip's messages and exit 1, as the route invargs do (above). No VM row compares a refusal's rc. Recorded only.
- **`maddress` has no 7.2.0 knob.** 7.2.0 read every group from procfs, and no corpus replays a 7.2.0 show through goip; the VM moves to 7.3.0 in NX4d. goip is 7.3.0's multiaddr_list, procfs fallback included.
- **The link-layer groups are checked live, not offline.** The workbench keeps no copy of the guest's `/proc/net/dev_mcast`. `TestWsV730Maddr` reads `testdata/maddr/dev_mcast`, d0's five groups in dev_mc_seq_show's format, rebuilt from the rows' ip.out. The rows check the merge, the order, the netlink half and the requests; the live comparison on `l` and NX4d's VM rows check the procfs half.
- **The test replay keeps each dump's own family.** ReplaySource answers a dump with every reply of its type in the capture, so both families' groups would come back twice. The test's wrapper keeps the requested family, as the kernel does. goip, like accept_maddr, does not check ifa_family.
- **A candidate iproute2 bug, found by reading: read_igmp overflows `name`.** igmp_mc_seq_show prints `%d\t%-10s:`, so a name of 10 or more characters runs into its colon. For a 15-character name, `sscanf(buf, "%d%s", &m.index, m.name)` writes 16 characters and a NUL, 17 bytes, into `char name[IFNAMSIZ]` (ip/ipmaddr.c:152, 7.3.0-27). An unprivileged `unshare -rn` with a dummy `abcdefghijklmno` shows the line as `2\tabcdefghijklmno:     1      V3`. The extra byte is a NUL on the first byte of `addr` (`flags`, already 0), so nothing visible changes, but it is a write past the array. 7.2.0 takes this path on every `maddr show`; 7.3.0 only when the netlink dump fails. 5734dc8a fixed the empty name, not this. Not yet run under ASan. Recorded here only. goip reads the name as one token and drops the colon.

  - **`tc -s -j qdisc show` for `fq` prints `"throttled"` twice in one object:** the u32 throttled_flows (tc/q_fq.c:531) and the u64 throttled events (:558). A JSON reader keeps one. Since d15e2bfc (2019-12-29).
  - **`tc -j qdisc show` for `fq` has the keys `"priomap "` and `"weights "`, with trailing spaces.** `open_json_array(PRINT_ANY, "priomap ")` makes the name both the text label and the JSON key (tc/q_fq.c:409, :419). Since 73a31c94 and 567eb4e4 (2023-12-06).

- **Decided: goip compiles in the stock name tables (2026-11-12, the user's choice, "Embed stock tables").** It carries the rt_dsfield iproute2 7.2.0 ships, rt_protos' `ovn` and `openr`, and the parity guest's /etc/protocols (iana-etc 20251215), not a host's own files. This replaces the no-config-files refusals for FRA_DSCP, FRA_IP_PROTO, tos and protocol names (NX7f, V062). goip prints the number for a name only a host's file has, as ip does without that line. ip loads rt_dsfield lazily, so DS field 0 prints `0` until another lookup has loaded the file; goip replicates that per process. That fault and an off-by-one in `rtnl_tab_initialize` are in [upstream/iproute2-rt-names-table-load.md](upstream/iproute2-rt-names-table-load.md). NX7e adds rt_realms under the same decision (V066): its one name, `0 cosmos`, has the same lazy load against the built-in `unknown`.
- **The rule readbacks and neigh's `openr` waited on a decision (superseded by the bullet above).** NX7a found the same split in rt_protos: ip's static table stops at eigrp, and the stock file adds `ovn` (84) and `openr` (99), so goip prints `proto 99` where ip prints `proto openr` (23 neigh readbacks, and any route with those protocols). goip refuses `rule show` when a rule carries FRA_DSCP or FRA_IP_PROTO, because ip names them from rt_dsfield and /etc/protocols, and goip reads no config files (`checkRuleRenderable`). FRA_TOS goes through the same rt_dsfield table, but goip prints it in hex, so 8 readbacks print `0xb8` where ip prints `EF`: the plausible-but-wrong line the refusal exists to prevent. The options: refuse a `tos` with a name in iproute2's stock table too, or carry the stock tables (the rt_dsfield iproute2 ships, and the protocols ip's guest had) and render all three.
